This is how the binaries stop being anonymous. A name typed into an installer is a
claim; a certificate is proof, and Windows only shows a publisher it can verify.

The version resource is generated by `build.py` (`write_version_file`), so it cannot
drift from `mimiccam/__init__.py`.

## What a certificate adds

Without one, Windows shows **Unknown publisher** and SmartScreen warns on every
download. With one, the UAC prompt and the download warning name the publisher, and
the signature is what a user can check after the fact.

| | unsigned | signed |
|---|---|---|
| SmartScreen | "Windows protected your PC" | publisher name, once reputation builds |
| UAC / installer | Unknown publisher | the certificate's subject |
| Properties → Digital Signatures | nothing | signature, timestamp, chain |
| a tampered download | indistinguishable | signature fails to verify |

Signing does **not** stop a fork. It means a fork can only appear as *the fork's*
publisher, because nobody can produce a valid signature under your name.

## What to buy

Publicly trusted code-signing keys have had to live in hardware since June 2023, so
"a .pfx you download" is no longer the normal case.

| option | cost | notes |
|---|---|---|
| **Azure Artifact Signing** (formerly Trusted Signing) | **$9.99/month**, Basic, up to 5,000 signatures | cloud HSM, no USB token, works from CI; requires identity validation of you as an individual or your organisation. The cheapest realistic route. |
| **OV certificate** from a CA (SSL.com, Sectigo, Certum, DigiCert…) | **~$129–300/year** | key on a FIPS token or the CA's cloud HSM; export is usually not possible, so sign from the machine or service that holds it |
| **EV certificate** | **~$300–900/year** | the strongest identity check; SmartScreen reputation is no longer the head start it once was |

Prices move; check the CA's page before buying. Whichever you choose, the certificate
subject should be **Ray Bekson** (individual) or your registered business name — that
string is what users will see.

## Wiring it into the build

One of three environment variables, then build as usual:

```bat
:: 1. A certificate file you can read (and its password)
set MIMICCAM_SIGN_PFX=C:\certs\mimiccam.pfx
set MIMICCAM_SIGN_PASSWORD=your-password

:: 2. A certificate already in your Windows store (My / Current User)
set MIMICCAM_SIGN_THUMBPRINT=0123456789ABCDEF...

:: 3. Any signing command, for a cloud signer (signtool with /dlib and /dmdf)
set MIMICCAM_SIGN_COMMAND=signtool sign /fd sha256 /tr http://timestamp.digicert.com /td sha256 /dlib "C:\...\Azure.CodeSigning.Dlib.dll" /dmdf "C:\...\metadata.json" {file}

python build.py --installer
```

`{file}` in option 3 is replaced with the binary to sign. With no variable set the
build prints that it is skipping signing and produces exactly what it produced before.

Every signature is timestamped, so it stays valid after the certificate expires
instead of every install suddenly warning about an old signature. After signing, the
build re-verifies each file with `signtool verify /pa` and fails if the signature does
not hold.

The setup is signed by `build.py` *after* Inno compiles it: Inno's own `SignTool`
directive cannot be driven from its command line here, because a `/D` value may not
contain spaces and every `signtool.exe` path does. The exe and the setup — the two
files a user downloads — are signed. The uninstaller that Inno embeds is not, so the
uninstall prompt may still say *Unknown publisher*.

**Check it yourself:**

```bat
signtool verify /pa /v dist\MimicCam\MimicCam.exe
signtool verify /pa /v dist\MimicCam-0.2.3-setup.exe
```

or right-click the file → **Properties → Digital Signatures**.

## The rights that actually get enforced

A signature proves who published a binary. These are what give you a legal claim when
somebody publishes one that is not yours:

- **Copyright** exists the moment the code is written; the git history dated from the
  first commit, the tags and the release notes are the record of it. **Registration**
  (U.S. Copyright Office, one application, roughly $45–65) is what upgrades it from a
  takedown request to statutory damages and attorney's fees. Register once the code is
  published — the registration covers the work as it stood on the deposit date.
- **The name** is what TRADEMARK.md claims. Filing *MimicCam* at a trademark office
  (USPTO, roughly $250–350 per class; class 9 covers software) converts ™ into ® and a
  presumption of ownership. Until then the claim rests on use in commerce plus the
  notices.
- **The canonical repository** is the reference point for all of the above: its commit
  history, its release tags and the checksums published with each release tie a
  download back to a moment and an author.

None of that requires code, and none of it is done for you by this repository — but
every notice in it is written to point at those three things.
